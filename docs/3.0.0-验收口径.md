# 3.0.0 验收口径

这份说明供维护者在版本更新后复查同一问题。把测试使用的安装包 SHA-256、Android API、设备型号、目标应用包名与版本、广告是否真实投放记录在同一批次。用户端累计明细、公开静态页面树和系统夹具各自回答不同的问题。

## 如何验证

| 结论 | 足以支持结论的证据 |
|---|---|
| 真实历史样式是否识别到正确出口 | 原始页面树的哈希、版本、预期控件标号，用当前应用实际匹配器回放得到的唯一节点。只检查正则或只读规则表都不够。 |
| 执行动作后内容是否出现 | 在同一广告会话记录出口状态、提交动作、窗口变化及实际目标回调或明确的普通内容状态。只有 API 返回 true 时标成“系统接受”。 |
| 红果是否提前退出 | 在同一版本真实投放中观察完整时间线，记录当时是否有独立可用出口及实际提前量。仅在解锁后翻页属于解锁后关闭。 |
| 小米/Redmi/POCO 能否长期运行 | 真实机型、MIUI/HyperOS 版本、授权开关、真实绑定、锁屏时长、系统回收/主动停止和恢复耗时。30 分钟／2 小时／8 小时／24 小时分开。 |
| 云盘、迅雷是否影响正常业务 | 同一版本分别跑广告、备份确认、下载、搜索、会员、文件分享/删除或支付等正常页。测试结果包含具体动作目标与普通页意外动作数。 |
| 新规则与旧数据兼容 | 两种签名 APK 安装检查，生产签名规则来源、基底、版本、启停状态、回滚与官方安装器覆盖升级，再回读用户设置。 |
| 隐私、资源与停用 | 检查合并 Manifest、离线无联网权限、受保护页、不保存截屏、样本导出前可编辑、用户停用和换前台后无旧动作。守护耗电须单列真机数据。 |

## 比率

提供一行一会话的 CSV，列名为 `case_id,environment,ad,safe_exit,detected,attempted,verified_closed,wrong_action`。1/0 表示本次实测真/假，空值表示未观察。每个环境内会话 ID 唯一；不要把多次点击、重复扫描或规则条数写成多个会话。用 `python tools/summarize_ad_evaluation.py <文件.csv>` 分环境计算五项比率：

| 指标 | 分子 / 分母 |
|---|---|
| 可操作广告成功率 | 确认成功关闭的会话 / 确认有安全出口的会话 |
| 识别召回率 | 命中经标注广告的会话 / 全部人工标注广告 |
| 广告处理覆盖率 | 确认成功关闭的会话 / 全部人工标注广告 |
| 动作后验证成功率 | 确认成功关闭的会话 / 实际提交动作的会话 |
| 正常页误触率 | 正常页发生非预期动作的会话 / 全部人工标注普通页 |

表中另给未知分母和未知结果。样本未覆盖、分母为零或静态回放无法观察点击时，结果为空。若要度量提前退出，应保留倒计时、动作开始与内容恢复的原始时刻，再决定可归因时间；完全漏检的广告只能通过独立标注发现。

## 使用与反馈
### 新增自己的规则

1. 在首页点「新增规则」。选择应用，再选「开屏广告」或「使用中弹窗」。从应用详情或「刚才没跳过」进入时会带入对应应用。已有脱敏样本时，可在反馈报告里从实际候选控件开始填写。
2. 填写广告上真实的按钮文字，弹窗还要填同一个弹窗上独立出现的提示文字。需要限定控件 ID 或页面时，展开「更多匹配条件」。
3. 点「预览规则」核对作用对象、广告场景和匹配条件。可先在目标应用试运行，试运行只观察；回到预览可以查看本条规则的试运行结果。
4. 点「保存」后可在自定义规则列表里看到它。取消「保存后启用此规则」可先存为暂停。在列表里可逐条启停、编辑或删除，连续弹窗按整组管理。应用排除项与全局开关继续生效。
5. 导入备份时，「只添加新规则」保留已有条目和启停状态；「替换全部」会再次要求确认。旧备份没有暂停字段时默认照常启用。暂停状态可以随新版备份保存与还原。

### 连接与反馈
授权后可以在「无障碍授权 → 测试本机点击」检查实际服务。这个测试只点击净屏自己的按钮。发现漏跳时，在首页点「刚才没跳过」，选择目标应用和广告类型。重现后可只提供基本报告，也可选脱敏样本；复制或保存前可以编辑报告。用户观察到自然结束、手动关闭或误点时，可在本机报告中标记。查看新口径的数据从「使用说明 → 查看本机处理统计」进入。
