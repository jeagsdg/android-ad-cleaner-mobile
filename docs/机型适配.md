# 重点机型与通用适配

以下五款是重点验收机型。OPPO Find X8 Pro 已有用户提供的 ColorOS 16.0 权限受限截图，系统授权入口仍需在该机复验。实际开屏识别按前台包名、控件、屏幕和规则判断。设备型号主要用于显示和选择系统设置规则。

净屏的最低安装版本是 Android 8.0（API 26）。通用功能使用 Android 公开 API。厂商的无障碍授权、进程管理、电池策略与系统设置布局需要分别核对，可在「管理开屏跳过 → 前台保活 → 检查后台限制」查看系统可提供的状态。实际 Android 版本、测试类型与范围见 [0.8 验收记录](../artifacts/验收记录-v08.md)。

系统版本无需预先填写：诊断报告读取 Android 版本、SDK、系统构建显示值、构建指纹、安全补丁日期和规则涉及的已安装应用版本。不会根据手机上市版本猜测用户现在装的系统，也不会读取设备序列号、Android ID 或 OAID。

## 如何提高覆盖而避免误操作

- 同一语义规则包含最多 6 条固定候选入口，每条最多 8 步；导航和目标扫描各最多 12 屏。
- 直达 Activity 被系统拒绝时，再尝试已知应用菜单；OPPO 搜索采用限定目标包的 `gs://search/setting` 设置入口。
- 菜单匹配使用明确文本、资源 ID 和受限设置图标规则，不猜点击坐标，不关闭整页全部开关。
- 只有找到明确名称的原生开关才操作，先保存原值再点击，再两次回读。灰态或自绘、同名歧义、权限/协议窗口均不会算成功。
- 实际成功的入口写入账本。恢复使用同一路径，核对系统构建和涉及应用版本；修改后的结果不确定时停止本轮任务。
- 网络过滤和开屏跳过独立于厂商设置规则，采用公共 Android API 和实际控件识别，不按这五款机型限制。华为的兼容 Android 系统、联想/摩托罗拉、中兴/努比亚等也可尝试这两项通用功能；这些品牌没有因此获得未经验证的系统开关规则。原生鸿蒙不支持本 APK。
- 网络过滤有 DNS、缓存和同域名边界；开屏需要可读且明确的跳过控件。视频插播不承诺解决。关闭个性化设置也可能只改变推荐方式。

## 小范围试用的验收标准

先检查一组明确广告项，核对系统原页面实际状态，再从改动记录恢复并核对原值。应用更新、支付、聊天、天气预警、搜索与下载等正常功能必须保留。失败项可附诊断报告反馈，机型适配状态以实际结果为准。
