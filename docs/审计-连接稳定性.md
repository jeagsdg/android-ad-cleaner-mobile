# 无障碍连接与小米后台守护

2026-11-26，基于当前工作副本的 2.4.0 源码。守护用于发现断连、等待 Android 重绑并给出恢复入口。开关状态、真实绑定回调、守护前台服务和广告结果是四项独立证据。小米、Redmi、POCO 的真实待机结果仍待采集。

## 代码审计与修复

| 风险 | 基线行为与触发条件 | 此次变更 |
| --- | --- | --- |
| 中 | `SkipKeepAliveService.checkRecovery` 每隔 30 秒重新投递检查，已绑定和长时间失联走相同路径。 | 已绑定时仅响应事件。失联先按 5、10、20、40、80、160 秒复查，再以 15 分钟为间隔观察。亮屏、解锁、前台返回、设置变化和服务回调可以提前检查。Handler 在深度睡眠时自然延后。 |
| 高 | `SkipKeepAliveService.recoveryConnection` 在刚启动时默认返回 CONNECTED。先解绑再启动守护的设备，在首次延迟检查前会导出错误状态。 | 查询同时看守护活动状态和实际服务引用，守护首条通知也读取绑定状态。读取连接状态失败时可显示 UNKNOWN。 |
| 中 | `CleanerService.onUnbind` 与 `onServiceConnected` 若在 1.5 秒合并窗口内连续发生，原先守护尚未进入等待状态，会漏记本次恢复。 | 在接到失联信号时即以单调时钟标记观察起点，在同一守护会话实际重连时记录已观察的等待时长。进程重建不会拼接前一次计时。 |
| 中 | `SkipKeepAliveService.enableRecovery/endRecovery` 会随守护开启普通保活，却无法判断普通保活此前是否独立开启。用户停止守护，或撤销无障碍再授权后，可能继续留下普通保活通知。 | 新会话记录普通保活的原设置，结束守护时还原。通知的「停止保活」关闭两项。旧会话缺少来源标记，沿用其已存设置。 |

`CleanerService.onServiceConnected` 挂载当前实例，`onUnbind` 和 `onDestroy` 只在实例仍是当前连接时记一次断连。`onInterrupt` 中断反馈，绑定保持。静止页面长时间没有无障碍事件，状态仍依据生命周期回调。设置中净屏被移除时结束守护，不写系统授权。未配置开机自启、重启闹钟或唤醒锁。Android 7.0–8.1 保留既有 30 秒通知权限可用性检查，这项检查与连接复查分别计数。[Android 无障碍服务生命周期](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)

## 怎样读本地诊断

| 字段 | 含义与边界 |
| --- | --- |
| `accessibilitySwitchEnabled`、`accessibilityServiceConnected` | 前者为系统选择列表中是否包含净屏，读取被拒时为 null。后者为本进程中实际收到连接回调且尚未解绑的实例。开关选中但当前无实例时，等待系统连接。 |
| `observedAccessibilityDisconnections` | 新版记录到的解绑或销毁次数。进程被直接杀死可能收不到回调。用户主动关闭也可能触发解绑，因此次数不能直接换算为异常率。 |
| `lastObservedRecoveryWaitMillis` | 最近一次守护内观察到的恢复耗时，单位毫秒。在守护开启前已失联时，以开始观察为起点。缺少测量返回 null。 |
| `lastWatchResumeTrigger` | 最近一次守护续接的触发方式。SYSTEM_RESTART 为 Android 重启该守护，FOREGROUND_SAME_PROCESS 为返回前台接续同进程会话，FOREGROUND_RESOURCE_EXIT 为同次开机且退出记录支持资源回收。此字段描述守护程序本身。 |
| `savedWatchResumeDisposition` | 有已保存、当前未运行的守护会话时，ALLOWED 表示会话身份允许前台接续，UNVERIFIED 表示开机或进程退出证据不足，DISARM 表示应结束会话。真正续接还会检查授权、通知和功能开关。 |
| `recoveryTimedChecksThisSession` | 当前守护会话已执行的定时连接复查次数。事件检查、通知检查和广告扫描另算。 |
| `backgroundRestricted`、`batteryOptimizationExempt`、`powerSaveMode`、`deviceIdleMode` | 导出时的 Android 系统状态。API 24–27 的后台限制读数为 null。这些值须结合观察时的 HyperOS 设置解读，不能还原早先断连的原因或机型的私有策略。[Android 后台限制接口](https://developer.android.com/reference/android/app/ActivityManager#isBackgroundRestricted%28%29) |

Android 杀掉进程时可能没有销毁回调。恢复前分别检查已授权的守护会话、开机次数、拥有者进程与系统退出记录。Android 11 起有明确的同次开机资源回收证据时可在前台续接。旧系统无法查证退出原因时保留未确认状态，等待 Android 自己的服务重启或用户再次开启。用户在 Android 13 活跃应用列表里点「停止」，系统可移除整个进程。重新使用时打开净屏并检查授权与守护。 [Android 前台服务停止行为](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)

## 验证范围

本轮使用 Robolectric 驱动 Android 生命周期与主线程虚拟时间。覆盖开关撤销、保活通知停止、用户主动停止、存量守护迁移、资源回收、跨开机保护、短时解绑重绑，以及长时静默。测试进程设置了小米品牌，本轮未接入 HyperOS 真机。

修改前守护回归 25/25 通过。修改后在 API 24、26、34 合计 37/37 通过，另在 API 34 独立测量两种状态的连接复查次数。模拟等待期间没有亮屏、进入前台或改变设置。原版只在临时测试副本的 `recoveryCheck` 回调入口增加计数，新版读取同一入口的诊断计数。[原始计数与源码哈希](../artifacts/connection-watch-20261126.json)

| 30 分钟虚拟时间内的连接定时回调 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 保持连接，无页面事件 | 59 | 0 |
| 开关保持开启，服务持续未绑定 | 59 | 7 |

计数覆盖守护连接定时器。系统设置观察、通知权限检查、CPU 耗时、电量和真实后台存活时间另计。短断连回归在虚拟时钟上间隔 250 毫秒，导出恢复耗时也为 250 毫秒。进程已死时，净屏自身无法在后台补记当时的状态。

## HyperOS 真机验收记录

每行应分别跑熄屏待机和正常使用。记录型号、HyperOS 构建号、Android 版本、安装包版本、守护选项、系统自启动和电量策略。用同一份诊断取前后差值，人工记下发生时刻、广告页是否有安全出口、实际有无处理和如何恢复。进程突然退出无回调时标明缺失，正常页面没有事件不记断连。

额外逐项记录划除最近任务、系统后台清理、内存压力、省电和超级省电、手机重启、应用覆盖升级、系统升级、手动撤销再授权。分别截取动作前、动作后及首次返回净屏三个时点的状态，区分系统自行重绑和打开净屏才恢复。各机型后台自启动入口可能不同。 [小米 14T 官方设置说明](https://www.mi.com/uk/support/faq/details/KA-507608/)
