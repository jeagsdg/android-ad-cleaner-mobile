# 3.0.0 审计基线与应用证据

## 应用覆盖

2.4.0（26）的安装包内有 157 条开屏候选、251 条应用内候选。两类分别涉及 125、172 个包，交集 36 个，合计 261 个。3.0.0（27）增加一条中国移动云盘原生轮播弹窗候选，共 409 条，应用包总数仍为 261。通用 SDK、用户自定义条目、精选增量包和只在 Java 中实现的识别逻辑分别维护。

[适配质量矩阵](适配质量矩阵.json) 每个包一行，包含名称、两类条数、场景、目录来源及数组下标、快照引用、已检查样本数、通过离线断言的样本数、对应版本与最后验证日期。用 `python tools/build_coverage_matrix.py` 根据两个实际安装资产与[样本索引](适配样本索引.jsonl)重新生成。包名和具体树的 `treeId` 联合去重。快照只有链接时不增加已验证数量，同一棵树上的多个检查只计一份样本。

索引中 `observed_offline` 记录读取过的树或回放选择结果；`asserted_offline` 表示该树至少一项明确预期已经核对。每项检查记录所用版本，历史结果保留当时的日期。正例、负例和边界样本都需要保留；这些数量不能作关闭成功率的分母。索引仅保存应用、版本、节点数量、场景、校验值及匹配结果。原始截图和节点正文没有加入交付文件。

当前索引有 344 棵树、77 个包。其中 311 棵属于内置目录里的包。13 个目录包至少有一棵树通过明确节点或排除断言，覆盖 76 棵不同的树，其余 248 个目录包保留候选状态。

### 状态判读

| 状态 | 取证条件 |
| --- | --- |
| 仅有候选 | 安装资产有条目，目前收录的证据中没有通过的离线断言。可另有已读快照。 |
| 离线样本已验证 | 在指定历史树上核对了预期目标或拒绝动作。范围限该树、该场景和该次实现。 |
| 模拟器已验证 | 须用具体目标应用在模拟器上记录广告前后变化。仿真应用的设备回归另列。 |
| 真实设备已验证 | 须在物理设备上记录目标版本、实际投放、出口与动作后结果。 |
| 缺少样本 | 样本索引没有对应实树，或缺少所反馈广告的对应版本和过程。 |
| 需要重新适配 | 有可操作出口的已确认广告在最新版仍漏检，或原候选选错控件。按场景判定。 |
| 当前无法安全处理 | 页面存在广告，但缺少可区分的出口，或与正常业务控件冲突。按场景判定。 |

本轮没有外接手机。真实关闭结果、成功率和误触率均保留为空。用户提到的其他几十个应用没有具体名称或事件样本，待取得反馈后归入对应包。

## 设备边界与性能口径

工程声明最低 API 24，编译及目标级别均为 35。现有可启动镜像为 API 27（Android 8.1）、34（Android 14）和 35（Android 15）。开始时 API 36 的 SDK 子目录只有安装器残留。随后补充 Google 官方 API 24、26、29、30、31、33、36 的 AOSP x86_64 镜像，分别校验原始归档再使用。具体启动与测试结果见设备验收记录。历史 API 25/30 日志、Robolectric SDK 与平台编译 JAR 均独立于本轮设备测试。

2026-11-26 从公开 2.4.0 源码重建完整版与离线版，分别通过 459 和 418 项检查，均 0 失败、0 跳过，Lint 分别 4、2 条警告及 0 错误，APK 权限和签名校验通过。首份内部开发构建使用过版本名 2.5.0（27）。其 489 项完整版检查中，488 项通过，一项事件序列回归。B 站连续独立开屏预期点击节点 190、20，实际只点 190。相同代码的六份历史静态回放报告逐行相同。该候选保留为中间取证。

Android 15 隔离模拟器已从正式 2.4.0（26）通过净屏的更新界面进入系统安装器，覆盖升级至最终 3.0.0（27）。完成后再次读取已安装 APK，SHA-256 为 `9f104004f95894d3f42c91f51d221bd0dc8f4cca4dc6e1e6f2ebf5b4a13596d8`，用户开启的开屏、弹窗、明细与系统无障碍授权保留。演练使用同证书测试器预置最终清单和下载完成的安装包；本次测量起点位于旧版客户端发现已下载更新之时。

性能夹具每个场景执行八次，采集本地测试按钮创建至夹具收到关闭回调的毫秒值。P95 使用排序后第八个样本。它包含窗口切换、系统事件、按钮等待和动作分发时间；与“出口可操作到发起动作”使用不同起止点。旧版发行记录在 Android 15 的普通开屏、延迟开屏、应用内弹窗分别为 8/8，P95 分别为 1472、1466、1351 ms。真实设备长时功耗与小米后台存活率缺少本轮测量。

### 复现方法

使用 Gradle 8.8、JDK 17/21、SDK 35；`-PofflineOnly=true` 选择无网络版。同一个 Variant 的输出目录会复用，每版构建后分别保存 APK、测试 XML 及 Lint XML，再运行另一版。签名正式包与调试包使用不同证书，设备测试 APK 需要和被测应用同证书。

1. 每版运行 `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest :fixture:assembleDebug`。使用 `tools/verify_apk.py` 的 `--variant full|offline --build-type debug` 核对安装包权限、签名和打包资产。仓库的 Android verification 工作流在两个独立任务执行相同检查。
2. 为设备专项使用空白测试模拟器；安装目标 APK、androidTest APK 和 fixture APK。设备测试会清空测试环境里的无障碍服务列表并绑定净屏，使用单独测试用户数据。分别运行 `adb -s <测试模拟器> shell am instrument -w -r -e suite <套件> app.clearscreen.test/app.clearscreen.DeviceChecks`。记录 `ad-latency`、`countdown-ad`、`keepalive`、`connection-check` 的输出，并核对最后的 PASS 与 instrumentation 结果码。
3. 树读取计数使用 `python tools/prepare_root_read_benchmark.py <冻结源码目录> <新的测试目录>` 生成独立探针版。构建该副本的 debug 与 androidTest APK，在同一模拟器用上述 `ad-latency` 套件。仅计扫描器对活动根节点的请求，从每次启动夹具前至该次结果核对结束。测量工具自身查询、窗口候选数及框架内部缓存命中不包含在该计数。
4. 同时安装探针副本的 fixture APK，在运行前清空测试客体 logcat，保存 `ClearScreenBench` 标签。按钮首次即将绘制且可见、可用、可点击时记录 `ready`，提交并获得接受的节点动作记录调用前的 `action`，夹具处理回调记录 `callback`。三者共用设备的纳秒单调时钟。在一个夹具实例中按时间配对；缺失任何一个时间点的样本单列。
5. 空闲测量先运行探针套件 `idle-ready` 确认服务绑定并开启两类跳过，返回启动器，亮屏、网络关闭、稳定五秒，再运行 `python tools/read_idle_profile.py --serial <测试模拟器> --output idle.json`。每次记录约两秒的进程用户态及内核态 CPU 时间差和系统报告的 PSS，共八次。CPU 以单个核心为 100%，PSS 单位为 KiB。

## 最终候选性能复测

同一 Android 15 AOSP 模拟器使用专用测量副本记录可见且已启用的按钮首次绘制与发起动作的时间。每版每场景 8 次。根节点请求为净屏扫描器调用次数，不含测试裁判。

| 场景 | 2.4.0 P50 / P95（毫秒） | 3.0.0 P50 / P95（毫秒） | 两版根节点请求 P50 |
|---|---:|---:|---:|
| 普通开屏 | 505 / 1172 | 568 / 988 | 12 / 12 |
| 延迟开屏 | 479 / 751 | 494 / 801 | 18 / 18 |
| 使用中弹窗 | 530 / 577 | 551 / 613 | 16 / 16 |

500 ms 的建议动作 P95 在这三个场景均未达到。普通开屏尾延迟下降，延迟开屏与使用中弹窗没有改善；每种只有 8 次，小幅差异仍受主机调度影响。空闲连接服务、屏幕开启、网络关闭、桌面在前台，各采 8 次。单核 CPU 占用中位数 1.17% → 1.16%，PSS 中位数 46,081 → 46,732 KiB。这是短时资源观察，真机电池耗电和长期存活仍待验证。[每次测量与运行条件](../artifacts/3.0.0-识别延迟与资源.json)
